# stdcell_gen: generated ics55 standard cell libraries

Two open standard cell libraries for ICsprout 55 nm (1.2 V core SVT devices `nm1p2_svt_lp` /
`pm1p2_svt_lp`), generated by [stdcell-gen](https://github.com/ckdur/stdcell-gen) (commit `c446888`,
`make -f Makefile.<lib> deliverable`, 2026-11-15). They are meant for place and route with LibreLane /
OpenROAD in this PDK, next to the vendor 7-track (`ics55_LLSC_H7C*`) and private 9-track libraries.

| Library | Height | Site | Cells | With liberty |
|---|---|---|---|---|
| `ics55t9` | 1.8 um (9 tracks of 0.2 um) | `obssite` 0.2 x 1.8 | 437 | 387 |
| `ics55t7` | 1.4 um (7 tracks) | `obssite` 0.2 x 1.4 | 405 | 353 |

Cell and pin names are the generator's (TSMC style): `ND2D1` (`a1 a2 -> zn`), `DFCNQD1`
(`d cp cdn -> q`), drive strength after `D`. `<lib>/cell_list` has the cells, and
`<lib>/doc/datasheet/index.html` documents every cell (function and table, pins, size, layout
picture, timing at tt).

## Contents

```
stdcell_gen/
  <lib>/                       # laid out like icsprout55/libs.ref/<lib>/
    gds/<lib>.gds.gz           # all cells, one top cell each (gzipped here, install.sh unpacks)
    lef/<lib>.lef              # SITE obssite + one MACRO per cell (pins, OBS); no tech layers
    liberty/<lib>_tt_1p20v_25c.lib.gz # NLDM, typical 1.2 V 25 C (gzipped)
    liberty/<lib>_ss_1p08v_125c.lib.gz  # slow 1.08 V 125 C
    liberty/<lib>_ff_1p32v_m40c.lib.gz  # fast 1.32 V -40 C
    verilog/<lib>.v            # functional models (power pins under `ifdef USE_POWER_PINS)
    verilog/<lib>_bb.v         # blackboxes
    cdl/<lib>.cdl              # LVS netlists (the ones the cells were LVS checked against)
    spice/<lib>.spice          # simulation netlists (MOS as X instances of the PDK model subckts)
    doc/datasheet/             # index.html + img/
    doc/verification/          # drc_lvs.txt (per cell), verilog.txt (models vs netlists)
    cell_list, README.md       # README: the status table of this build
  librelane/<lib>/config.tcl   # the draft library configuration as delivered (superseded by
  librelane/<lib>/synth_exclude.cells   #  icsprout55/libs.tech/librelane/<lib>, see below)
```

## What place and route needs to know

- **Technology**: use the PDK's tech LEF (`icsprout55/libs.tech/librelane/N551P6M_ecos.lef`); the
  layer names (`MET1`, `VIA1`, `MET2`, ...) match. The cell LEF only adds `SITE obssite` (both
  libraries use this name with different heights: do not load both in one design).
- **Power**: pins `vdd` (`USE POWER`) and `vss` (`USE GROUND`), lower case (the vendor libraries use
  `VDD`/`VSS`: the global connections of the PDN must use these names). Rails on MET1, 0.16 um high,
  centred on the bottom (vss, y = 0) and top (vdd, y = height) edges of every cell; rows flip as usual.
- **Tapless cells**: no bulk contacts in the cells. Place `TAPCELL` (0.8 um wide) in every row at
  most ~50 um apart (latch-up rule LU_S_2 is 35 um from any source/drain to a tap). The cells were
  checked abutted (all cells in rows, alternate rows mirrored, fillers around) with no DRC markers.
- **Fillers / ends**: `FILL1 FILL2 FILL4 FILL8 FILL16 FILL32 FILL64` (site multiples). No endcap cells:
  close the rows with fillers. `FILL1` alone has a MET1 minimum-area marker that disappears when
  abutted. Decaps: `DCAP DCAP4 DCAP8 DCAP16 DCAP64` (ics55t7 only).
- **Ties**: `TIEH/z`, `TIEL/zn`. **Antenna diode**: `ANTENNA/i`, but the LEF has no ANTENNA* data
  (no gate/diffusion areas on any pin): OpenROAD's antenna checks and repair cannot use it as it is.
- **Pins**: signal pins on MET1; 159 (ics55t9) / 152 (ics55t7) cells also have MET2 pin shapes and
  ~210 / ~228 cells have MET2 obstructions (the cells route internally on MET2 where poly and MET1
  are not enough), so MET2 is not free over every cell. The pins are where the x compaction left
  them, not on the 0.2 um routing grid (stdcell-gen ticket STDCE-17): pin access is the first thing
  to watch in detailed routing. There is no `tracks.info` for these libraries yet (MET1/MET2 pitch
  0.2 um like the vendor ones).
- **LVS**: the cells are LVS clean against `cdl/<lib>.cdl` with `icsprout55/libs.tech/klayout/tech/ics55.lvs`
  in `tapless=true` mode (wells tied to the rails). DRC: `ics55.drc`, clean except the density rules
  and the latch-up / floating well rules a single cell cannot satisfy.

## Liberty

- lctime (our fork) + ngspice with the PDK models (`ngspice/ICsprout_55LLULP1225_V1p1_hsp.lib`,
  sections `tt_mos`, `ss_mos`, `ff_mos`). Tables 6 x 6: input slew 0.1 - 3.2 ns, output load
  **0.05 - 1.6 pF**. The smallest load (50 fF) is above most nets of a small design: STA extrapolates
  below the table. Re-characterize with smaller loads before trusting absolute timing (stdcell-gen:
  `CHAR_LOADS="..." make -f Makefile.<lib> corners`, after deleting `tmp/char_<lib>/`).
- Content: input pin capacitances, delay and transition per arc, setup / hold / recovery / removal /
  minimum pulse width of the flip-flops, switching energy, leakage per input state
  (`cell_leakage_power`), `pg_pin`s, area from the LEF.
- **Not in the liberty** (exist in GDS/LEF/Verilog only, keep them out of synthesis): the latches and
  integrated clock gates (`LH*`, `LN*`, `CKLHQ*`, `CKLNQ*`: lctime cannot characterize latches), the bus
  holder `BHD`, and the physical cells (`FILL*`, `TAPCELL`, `ANTENNA`, `DCAP*`). `TIEH`/`TIEL` are in the
  liberty with their function but no timing or leakage.
- Also missing: the enable arcs of the tri-state buffers (`BUFTD*`: only `i -> z`), and the internal
  power of the flip-flops (OpenSTA reports 0 internal power for sequential cells).
- Some arcs of multi-stage cells have slightly negative delays at the fast corner with the slowest
  input slew (the output switches before the input reaches 50 %); OpenSTA accepts them.
- Checked: every corner file loads in OpenSTA without warnings; corner order ff < tt < ss holds for
  every cell (median ss/tt 1.70, ff/tt 0.68 for ics55t9); a small counter synthesizes with yosys
  (`dfflibmap` + `abc` on these files) and passes STA and `report_power`.

## LibreLane integration

Done in this PDK (2026-11-15): `librelane --pdk icsprout55 --scl ics55t9` (or `ics55t7`).

- `install.sh` copies `stdcell_gen/<lib>` to `icsprout55/libs.ref/<lib>`, unpacks GDS and liberty
  and adds what the flow needs on top of the delivered views:
  - `verilog/<lib>.v`: one-line `if (...) x <= y;` statements split in two
    (`hacking/verilog_models.py`; LibreLane's lint preprocessing deletes such lines as if they were
    cell instances, and the flop models then do not parse);
  - `liberty/<lib>_*.lib`: `max_capacitance` 1.6 pF on every output pin and the library defaults
    1.6 pF / 3.2 ns, the characterized range (`hacking/liberty_limits.py`; OpenROAD CTS refuses
    buffers without a max capacitance, CTS-0002);
  - `lef/<lib>_openpdk.lef`: the per pin `ANTENNAGATEAREA` / `ANTENNADIFFAREA` from Magic
    (`hacking/magic/lef_antenna.py`, table `libs.tech/librelane/<lib>/antenna.pins`), and
    `DATABASE MICRONS 1000` instead of 2000 (OpenROAD discards a cell LEF with more units than the
    tech LEF; all coordinates are on the 0.001 um grid);
  - `liberty/<lib>_antenna.lib` for the `ANTENNA` diode (`hacking/antenna_liberty.py`);
  - `spice/<lib>_lvs.spice`, the netgen reference (`hacking/magic/lvs_netlist.py`).
- `icsprout55/libs.tech/librelane/<lib>/` (`config.tcl` sourcing `ics55t_common.tcl`,
  `tracks.info`, `synth_exclude.cells`, `antenna.pins`) and a branch in the PDK `config.tcl`.
  `vdd` / `vss` are the cell power pins (`SCL_POWER_PINS`, `VDD_PIN`), the nets stay `VDD` / `VSS`.
- `synth_exclude.cells` (also the PnR exclusion) has the physical cells, `BHD`, the latches /
  clock gates and every cell with a signal pin the OpenROAD detailed router has no access point
  for (DRT-0073), found by `hacking/pin_access_scan.tcl` (every cell placed in both row
  orientations): 138 cells of ics55t7, 164 of ics55t9. The pins are 0.09 um wide (the narrowest
  VIA1 of the tech LEF has a 0.10 um MET1 pad) with neighbours at the minimum spacing, or covered by
  the cell's own MET2. ics55t9 keeps a single flip-flop, `DFCNQD1`; ics55t7 keeps 7 of 17.

`demo_counter` with either library (run tags `debug_ics55t9` / `debug_ics55t7`): route DRC 0,
Netgen and KLayout LVS 0, OpenROAD and KLayout antenna 0, power grid 0. KLayout DRC as with the
vendor 7-track library (density minima of the unfilled die, CHIPEDGE_EN_1) plus findings that come
from the cells:
- `PP_S_1` between the `TAPCELL`s of two rows on top of each other (same x);
- `V1_W_1` (ics55t7, `XNR2D2`): a router VIA1 overlapping a VIA1 inside the cell; the cell LEF has
  no VIA1 obstructions, so the router does not see the cuts of the cell;
- `M2_S_5` (ics55t7, next to `DEL005`): MET2 line end spacing, not in the LEF rules.

Still open on the library side: pin access (STDCE-17), VIA1 obstructions in the LEF, TAPCELL
implant at vertical abutment, latches in the liberty (designs with latches do not synthesize),
the 50 fF minimum table load.

## Regenerating

In stdcell-gen (see its README, "Logic, Verilog and datasheet" and "Characterization"):

```
make -f Makefile.ics55t9 -j16 PYTHON3=<venv with lctime deps> corners      # liberty (hours)
make -f Makefile.ics55t9 PYTHON3=<venv> deliverable                        # tmp/deliverable/ics55t9/
```

Open items are tickets in the `stdcell` workspace of bugs.ckdur.dev: STDCE-16 (views and
sign-off), STDCE-17 (pin access / site), STDCE-35 (latches), STDCE-36 (ties, tri-state enables,
flip-flop internal power), STDCE-37 (the table loads and slews are too large for 55 nm),
STDCE-33 (ics55f, the 12-track library, not characterized).
